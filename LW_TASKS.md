# Задания к лабораторным работам

## Распределение оценок за готовый функционал проекта на основе 2248_FoodDeliveryService

- 4-5 Написание основной части сервера(состоит из 5-и лабораторных работ)
- 6-7 Написание сервиса обработки заказов(отдельный сервис, изменяющий статус заказов - имитация обработки); Связывание с осн. сервисом через брокер RabbitMQ – осн. сервис отправляет сообщение о поступлении нового заказа, сервис обработки - об изменении статуса заказа.
- 8 Логирование с помощью Grafana+Prometheus; Настроить деплоймент используя Docker compose
- 9-10 Написание сервиса нагрузки и демонстрация полной работоспособности, используя дашборды в графане 

## Лабораторные работы по основной части сервиса

### ЛР1 - Написание пустого Http сервера
Требуется написать http сервер на Golang(Go), в котором будет 1 тестовый GET эндпоинт(/test), который будет возвращать строку “Hello!”.  Сервер должен соответствовать чистой архитектуре(иметь 3 слоя с четкой изоляцией через интерфейсы). Обработка запроса должна задействовать все 3 слоя. Также необходимо реализовать у сервера безопасное завершение работы(graceful shutdown) при получении сигнала завершения. В результате сервер должен уметь включаться, работать долгое время без ошибок и выключаться с технологией graceful shutdown.

### ЛР2 - Добавление и инициализация БД
К существующему серверу требуется дописать подключение к БД PostgreSQL. Необходимо также прописать инициализацию таблиц. Для проверки работоспособности напишите еще один POST хэндлер(/dbtest) так, чтобы при получении запроса в базу писалась строка из тела запроса. Работа с БД должна находиться на слое изоляции repository. В результате сервер должен уметь подключаться к БД и производить операции чтения/записи.

### ЛР3 - Написание хэндлеров для работы с пользователем
Необходимо написать хэндлеры для авторизации пользователя и получения им сессионного токена авторизации(JWT):

- Хэндлер создания(регистрации) пользователя(должен быть в БД)
- Хэндлер авторизации, получения сессионного токена

В результате сервер должен уметь создавать новых пользователей и генерировать JWT сессионный токен существующим.

### ЛР4 - Написание хэндлеров для работы с заказами
Необходимо написать хэндлеры для работы с заказами:

- Хэндлер создания нового заказа
- Хэндлер проверки статусов всех привязанных к пользователю заказов

### ЛР5 - Написание middleware для взаимодействия пользователя с сервисом
Требуется написать middleware, который будет получать на вход сессионный токен(JWT) и возвращать в хэндлеры заказов ID пользователя, кому принадлежит этот токен. В результате сервер должен уметь создавать заказы, а также возвращать списки заказов отдельно для разных пользователей.
